# Тема 5. 3D-моделі та формати обміну даними

## 1. Як влаштована 3D-модель

Будь-яка тривимірна модель, яку показує комп'ютер у реальному часі, складається з простих елементів.

**Вершина (vertex)** — точка у просторі, задана трьома координатами X, Y, Z.

**Ребро (edge)** — відрізок між двома вершинами.

**Полігон (грань, face)** — плоска фігура, обмежена ребрами. Зазвичай трикутник, рідше чотирикутник. Відеокарта вміє швидко малювати саме трикутники, тому перед виведенням на екран усі поверхні розбиваються на них.

**Сітка (mesh)** — сукупність усіх полігонів, що утворюють поверхню об'єкта.

**Кількість полігонів** — головний показник «важкості» моделі. Простий куб — 12 трикутників. Детально змодельований стілець — кілька тисяч. Повна BIM-модель багатоповерхового будинку з армуванням і кріпленням — десятки й сотні мільйонів.

**Матеріал** — опис того, як поверхня виглядає: колір, блиск, прозорість, шорсткість.

**Текстура** — растрове зображення, накладене на поверхню: малюнок цегляної кладки, деревини, бетону. Текстури займають основну частину пам'яті відеокарти.

**Освітлення.** Два підходи:
- *У реальному часі* — тіні й освітленість перераховуються в кожному кадрі. Гнучко, але витратно.
- *Попередньо прораховане (запечене, baked)* — освітлення розраховується один раз і зберігається в текстурах. Працює дуже швидко, але сцену не можна змінювати. Для архітектурних VR-сцен застосовується найчастіше.

## 2. Чим модель для VR відрізняється від моделі для креслень

BIM-модель створюється для іншої мети: з неї отримують креслення, специфікації, обсяги робіт, кошторис. Тому в ній усе точне й детальне — кожен шар стіни, кожен стрижень арматури, кожен кріпильний елемент.

Для віртуальної реальності важливе інше: модель має виглядати достатньо правдоподібно і при цьому малюватися 72–90 разів на секунду, причому двічі — окремо для кожного ока. Фактично це 144–180 кадрів за секунду.

| Критерій | Модель для креслень (BIM) | Модель для VR |
|---|---|---|
| Головна вимога | точність і повнота даних | швидкість відображення |
| Деталізація | максимальна | достатня для сприйняття |
| Приховані елементи | потрібні (арматура, шари) | зайві, їх видаляють |
| Матеріали | інформаційні (марка бетону) | візуальні (як виглядає) |
| Розмір | не критичний | критичний |

Звідси головний висновок теми: **модель із Revit чи ArchiCAD не можна просто так завантажити в шолом**. Її потрібно підготувати.

## 3. Формати обміну даними

**Формати BIM та проєктування:**
- **IFC** (Industry Foundation Classes) — відкритий міжнародний формат обміну BIM-моделями. Зберігає не лише геометрію, а й інформацію про елементи: тип, матеріал, властивості. Основний формат передачі моделі між різними програмами.
- **RVT** — власний формат Autodesk Revit.
- **PLN** — власний формат ArchiCAD.
- **SKP** — власний формат SketchUp.
- **DWG / DXF** — формати AutoCAD, переважно для 2D, але підтримують і 3D-геометрію.

**Формати геометрії для візуалізації та рушіїв:**
- **FBX** — найпоширеніший формат передачі геометрії, матеріалів та анімації в Unity й Unreal Engine.
- **OBJ** — простий і давній формат. Передає тільки геометрію й базові матеріали, без анімації.
- **glTF / GLB** — сучасний компактний формат, створений спеціально для реального часу та веб. GLB — це варіант, у якому модель і текстури зібрані в один файл.
- **USD / USDZ** — формат, розроблений Pixar, набирає поширення для обміну складними сценами.

**Типові маршрути передачі:**

```
Revit ──→ (прямий плагін) ──→ Enscape / Twinmotion ──→ шолом
Revit ──→ FBX ──→ Unity / Unreal Engine ──→ шолом
ArchiCAD ──→ BIMx ──→ планшет / шолом
ArchiCAD ──→ прямий зв'язок ──→ Twinmotion ──→ шолом
будь-яка BIM-програма ──→ IFC ──→ Navisworks / інша програма
```

**Що втрачається при експорті.** Це питання викликає найбільше проблем на практиці:
- при експорті у FBX чи OBJ **втрачається вся інформація про елементи** — залишається тільки геометрія. Віртуальна стіна перестає бути стіною й стає просто набором полігонів;
- часто «злітають» матеріали й доводиться призначати їх заново;
- може змінитися масштаб, якщо в програмах різні одиниці вимірювання (метри / сантиметри / дюйми);
- може зміститися початок координат — модель опиняється за кілометр від центру сцени;
- IFC зберігає інформацію, але спрощує складну геометрію.

**Правило:** якщо потрібна лише картинка — підійде FBX або glTF. Якщо потрібно, щоб у віртуальному середовищі можна було натиснути на елемент і побачити його характеристики — потрібен IFC або прямий плагін, який зберігає зв'язок із BIM-моделлю.

## 4. Підготовка моделі до віртуальної реальності

**Крок 1. Відсікання зайвого.** З моделі видаляють усе, що не буде видно: арматуру, внутрішні шари конструкцій, кріплення, сусідні секції будівлі, якщо оглядається лише одна. Часто це зменшує модель у кілька разів.

**Крок 2. Спрощення геометрії (децимація).** Зменшення кількості полігонів на складних елементах. Криволінійні поверхні, гвинти, профільовані деталі можна описати значно меншою кількістю трикутників без помітної втрати вигляду.

**Крок 3. Робота з повторюваними елементами.** Якщо в моделі тисяча однакових вікон, у пам'яті має зберігатися одне вікно, яке відображається тисячу разів у різних місцях (інстансування). Це дає суттєвий виграш.

**Крок 4. Оптимізація текстур.** Зменшення роздільної здатності текстур, об'єднання кількох текстур в одну (атлас), використання однакових матеріалів там, де це можливо.

**Крок 5. Рівні деталізації (LOD).** Для об'єкта готують кілька версій різної складності. Поки він далеко — показується спрощена, при наближенні — детальна.

**Крок 6. Розрахунок освітлення.** Для статичних архітектурних сцен освітлення запікають заздалегідь.

**Рівень деталізації під задачу.** Не завжди потрібна максимальна якість:
- *презентація замовнику* — важлива картинка: матеріали, освітлення, оточення;
- *технічна перевірка* — важлива точність геометрії, картинка другорядна;
- *навчальний сценарій* — важлива інтерактивність, модель може бути схематичною.

## 5. Продуктивність у реальному часі

**Рендеринг у реальному часі** — побудова зображення «на льоту», у момент показу. Цим він відрізняється від фотореалістичної візуалізації, де один кадр може прораховуватися годинами.

**Бюджет кадру.** При 90 кадрах за секунду на один кадр відведено близько 11 мілісекунд. За цей час відеокарта має намалювати всю сцену двічі — для лівого й правого ока. Якщо не встигає, кадри починають пропускатися, зображення смикається, у користувача з'являється нудота.

**Орієнтовні обмеження для автономного шолома (Quest 3):**
- кількість трикутників у кадрі — до 0,5–1 млн;
- кількість окремих матеріалів — бажано не більше кількох десятків;
- динамічних джерел світла — одиниці.

Для режиму з підключенням до комп'ютера показники значно вищі й залежать від відеокарти.

**Як перевірити продуктивність.** У рушіях і візуалізаторах є вбудовані лічильники: частота кадрів (FPS), кількість полігонів, кількість викликів відмальовування (draw calls). Їх слід контролювати ще до завантаження сцени в шолом.

**Типова помилка початківця:** експортувати повну модель будівлі з усіма розділами, завантажити в шолом і зробити висновок, що «технологія не працює». Насправді не виконано підготовку моделі.
