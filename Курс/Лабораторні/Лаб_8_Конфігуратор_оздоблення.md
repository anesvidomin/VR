# Лабораторна робота № 8
## VR-конфігуратор оздоблення та складання застосунку під Quest 3

**Теми:** 7 (Ігрові рушії), 8 (Практичне застосування)
**Тривалість:** 6 годин (підсумкова робота)

### Мета роботи

Розробити інтерактивний VR-конфігуратор, у якому замовник самостійно обирає варіанти оздоблення та планування приміщення, зібрати його в автономний застосунок для Quest 3 і випробувати на реальних користувачах.

### Обладнання та програмне забезпечення

- Комп'ютер, шолом Meta Quest 3, кабель USB-C
- Unity з модулем Android Build Support
- Сцена з лабораторної роботи № 7
- Обліковий запис розробника Meta (режим розробника на шоломі)

### Короткі теоретичні відомості

Конфігуратор — один із найпоширеніших комерційних застосувань віртуальної реальності в будівництві. Замовник, який не вміє читати креслення й не уявляє, як виглядатиме приміщення, самостійно перемикає варіанти оздоблення та бачить результат у натуральну величину. Це скорочує кількість змін на етапі будівництва, прискорює погодження й використовується як інструмент продажу нерухомості.

Автономний застосунок потрібен для того, щоб конфігуратор працював без комп'ютера: шолом із готовим файлом можна передати у відділ продажів, винести на виставку або віддати замовнику.

### Вихідні дані

Приміщення з попередніх робіт: квартира, офіс, кафе, побутове приміщення. Для кожної поверхні слід підготувати не менше трьох варіантів оздоблення.

### Порядок виконання роботи

**Завдання 1. Підготовка варіантів**

1. Визначити, що буде перемикатися. Мінімум:
   - підлога — не менше 3 варіантів (наприклад, ламінат, плитка, наливна підлога);
   - стіни — не менше 3 варіантів кольору або покриття;
   - фасад або віконні конструкції — не менше 2 варіантів;
   - меблювання — не менше 2 варіантів розстановки.
2. Підготувати матеріали в Unity: текстура, колір, шорсткість, масштаб накладання.
3. Скласти таблицю варіантів із зазначенням умовної вартості кожного (знадобиться для завдання 5).

**Завдання 2. Скрипт перемикання матеріалів**

4. Створити скрипт, що по черзі змінює матеріал заданої поверхні:

```csharp
using UnityEngine;

public class MaterialSwitcher : MonoBehaviour
{
    public Renderer surface;
    public Material[] options;

    private int index = 0;

    public void Next()
    {
        index = (index + 1) % options.Length;
        surface.material = options[index];
    }

    public int CurrentIndex()
    {
        return index;
    }
}
```

5. Додати скрипт до об'єктів підлоги, стін, фасаду.
6. Створити у сцені віртуальні кнопки, прив'язані до методу Next.

**Завдання 3. Перемикання варіантів розстановки**

7. Створити дві-три групи об'єктів із різними варіантами меблювання.
8. Використати скрипт перемикання груп (аналогічно до роботи № 7) так, щоб одночасно була видима лише одна група.

**Завдання 4. Панель керування**

9. Створити у віртуальному просторі панель керування з підписаними кнопками: «Підлога», «Стіни», «Фасад», «Розстановка», «Скинути».
10. Розмістити панель так, щоб вона була зручно досяжна з будь-якої точки приміщення, або прив'язати її до контролера.
11. Перевірити, що всі кнопки працюють у шоломі.

**Завдання 5. Підрахунок вартості**

12. Додати скрипт, що підсумовує умовну вартість обраних варіантів і виводить її на панель:

```csharp
using UnityEngine;
using TMPro;

public class PriceBoard : MonoBehaviour
{
    public MaterialSwitcher floor;
    public MaterialSwitcher walls;
    public float[] floorPrices;
    public float[] wallPrices;
    public TextMeshProUGUI label;

    void Update()
    {
        float total = floorPrices[floor.CurrentIndex()]
                    + wallPrices[walls.CurrentIndex()];
        label.text = "Вартість оздоблення: " + total.ToString("F0") + " грн";
    }
}
```

13. Перевірити, що значення змінюється при перемиканні варіантів.

**Завдання 6. Збереження вибору**

14. Додати кнопку «Зберегти вибір», яка виводить у журнал (або на панель) підсумковий перелік обраних варіантів.
15. Переконатися, що після огляду можна відтворити, що саме обрав замовник.

**Завдання 7. Складання автономного застосунку**

16. Перемкнути платформу проєкту на Android.
17. Перевірити налаштування графіки для мобільного процесора.
18. Увімкнути режим розробника на шоломі, підключити кабелем, підтвердити дозвіл на налагодження по USB.
19. Виконати складання й запуск застосунку на пристрої.
20. Зафіксувати розмір отриманого файлу, час складання та частоту кадрів в автономному режимі.
21. За потреби виконати оптимізацію до досягнення стабільних 72 кадрів за секунду.

**Завдання 8. Випробування на користувачах**

22. Запросити двох студентів з іншої підгрупи у ролі замовників — **без попередніх пояснень**.
23. Поставити завдання: обрати варіант оздоблення, що подобається, і вкластися в задану суму.
24. Зафіксувати: час виконання, які кнопки викликали нерозуміння, що довелося пояснювати, який варіант обрано.
25. Внести виправлення за результатами випробувань (зазвичай це підписи, розмір кнопок, розташування панелі).

### Зміст звіту

1. Тема, мета, опис приміщення.
2. Таблиця варіантів оздоблення з умовною вартістю.
3. Тексти скриптів із поясненням.
4. Знімки екрана різних варіантів оздоблення одного приміщення.
5. Знімок панелі керування.
6. Протокол складання застосунку: розмір файлу, частота кадрів в автономному режимі.
7. Результати випробувань на користувачах у вигляді таблиці.
8. Перелік внесених виправлень.
9. Висновки: чи може такий конфігуратор застосовуватися у реальній роботі та що для цього потрібно доробити.

### Контрольні питання

1. Яку практичну задачу вирішує VR-конфігуратор у роботі з замовником?
2. Чим автономний застосунок відрізняється від роботи з підключенням до комп'ютера?
3. Які кроки потрібні для складання застосунку під Meta Quest 3?
4. Поясніть роботу скрипта перемикання матеріалів.
5. Чому випробування на сторонніх користувачах дає більше, ніж перевірка розробником?
6. Які обмеження має автономний режим шолома за продуктивністю?

### Критерії оцінювання

| Критерій | Балів |

| Створено панель керування з підрахунком вартості | 2 |

### Примітка щодо організації

Робота є підсумковою й може виконуватися у групах по 2 студенти з розподілом: один відповідає за сцену й матеріали, другий — за скрипти й збірку. Випробування кожен проводить окремо. У звіті зазначається внесок кожного учасника.
